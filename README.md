## Главное за 30 секунд

> **Каждая команда, которая ходит в LLM, сейчас сама решает, как не отдать модели паспорт
> клиента.** PD-Guard делает это один раз и для всех: один сервис, одна политика на систему,
> один YAML — и маскирование, которое можно отмотать назад.

```text
Клиент Иванов Иван Иванович, дата рождения 12.03.1985, паспорт 4509 123456,
карта 4111 1111 1111 1111, CVV 123. Любит стихи Александра Пушкина.
```

```text
Клиент [ФИО_1], дата рождения [ДАТА_РОЖД_1], паспорт [ПАСПОРТ_1],
карта **** **** **** 1111, CVV ***. Любит стихи Александра Пушкина.
```

Пушкин остался Пушкиным: публичные лица, адреса отделений банка и номера договоров
отсекаются фильтрами релевантности. Модель отвечает про `[ФИО_1]`, а клиент получает
«Уважаемый Иванов Иван Иванович» — плейсхолдеры возвращаются на место по той же сессии.

<table>
<tr>
<td width="33%" valign="top">

**① Правила — это конфиг,<br/>а не код**

Типы ПД, способ маскирования,
демаскирование и доступ задаются
профилем системы. Файл
перечитывается на лету; битый
конфиг не роняет сервис —
остаётся предыдущая версия.

</td>
<td width="33%" valign="top">

**② Маска обратима<br/>и не хранит ПД в открытую**

Соответствие «маска → оригинал»
шифруется AES-256-GCM с ключом
сессии через HKDF. Повторный
запрос с тем же `payload_id`
идемпотентен — ретраи не плодят
новые маски.

</td>
<td width="33%" valign="top">

**③ Встраивается<br/>без переделки клиента**

Два режима: явный `POST /process`
и прозрачный прокси к
OpenAI-совместимому API. Прокси
маскирует `messages[*].content`
и демаскирует `choices[*]`
по JSON-путям из конфига.

</td>
</tr>
</table>

## Как это работает

```text
  ЗАПРОС                  ДЕТЕКЦИЯ                     РАЗРЕШЕНИЕ
  ├─ аутентификация       ├─ регулярки + валидаторы    ├─ пересечения по приоритету
  ├─ rate limit           │   (Луна, ИНН, СНИЛС, дата) ├─ фильтры релевантности:
  └─ нормализация    ──▶  ├─ словари (имена, города)   │   публичные лица, отделения,
     регистр, ё, NFKC,    ├─ структурные поля JSON     │   контекст организации
     карта смещений       └─ числа прописью       ──▶  └─ правила сочетаний
                                                          (ПИН только рядом с картой)
                                                                   │
                                                                   ▼
  ОТВЕТ LLM               VAULT                        МАСКИРОВАНИЕ
  └─ демаскирование  ◀──  ├─ AES-256-GCM, HKDF    ◀──  ├─ placeholder · partial
     на исходных          ├─ memory / Redis            ├─ token · synthetic
     позициях             └─ TTL 15 мин                ├─ hash · redact
                                                       └─ самопроверка на утечки
```

Нормализованный текст хранит карту смещений обратно в оригинал, поэтому детекторы
работают без учёта регистра и `ё`, а замена попадает ровно в исходные байты.
После маскирования детекторы прогоняются ещё раз по результату: всё, что нашлось,
уходит в метрику `pdg_leak_detected_total`.

## Быстрый старт

Нужен Rust 1.89+. Секреты читаются из окружения, в конфиге только ссылки `env:…`.

```bash
export PDG_MASTER_KEY=$(openssl rand -base64 32)
export PDG_KEY_CRM_SHA256=$(printf 'crm-secret' | sha256sum | cut -d' ' -f1)
export PDG_ADMIN_TOKEN_SHA256=$(printf 'admin-token' | sha256sum | cut -d' ' -f1)

cargo run --release
```

Сервис слушает `0.0.0.0:8080`, служебный порт — `127.0.0.1:9090`.
Путь к конфигу меняется через `PDG_CONFIG`, по умолчанию `config/config.yaml`.

## API

| Метод | Путь | Порт | Назначение |
|---|---|---|---|
| `POST` | `/process` | публичный | Маскирование и демаскирование одного текста |
| `POST` | `/process/batch` | публичный | Маскирование пачки текстов |
| `ANY` | `/proxy/{route}` | публичный | Прозрачный прокси к LLM по маршрутам из конфига |
| `GET` | `/health/live`, `/health/ready` | оба | Пробы живости и готовности |
| `GET` | `/metrics` | служебный | Метрики Prometheus |
| `POST` | `/admin/config/reload` | служебный | Принудительная перезагрузка конфига |

Система представляется заголовками `X-System-Id` и `X-System-Key`. Ключ сравнивается
с SHA-256 из конфига за постоянное время. Запрос без заголовков обслуживается политикой
`default_system_id`; пустое значение закрывает анонимный доступ.

**Контракт Приложения A.** Направление определяется по `payload_id`: первый запрос
маскирует, повтор с тем же id — демаскирует.

```bash
curl -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -d '{"payload":"Позвоните Петрову Сергею Викторовичу по +7 916 123-45-67","payload_id":"p42"}'
# {"result":"Позвоните [ФИО_1] по [ТЕЛЕФОН_1]"}

curl -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -d '{"payload":"Позвоните [ФИО_1] по [ТЕЛЕФОН_1]","payload_id":"p42"}'
# {"result":"Позвоните Петрову Сергею Викторовичу по +7 916 123-45-67"}
```

**Расширенная форма.** Шаг задаётся явно, в ответе — найденные сущности с позициями
до и после замены, `session_id` для демаскирования и статистика.

```bash
curl -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -H 'X-System-Id: crm-assistant' -H 'X-System-Key: crm-secret' \
  -d '{"operation":"mask","text":"Клиент Иванов Иван Иванович, паспорт 4509 123456"}'
```

```json
{
  "session_id": "01a0d252-5b3e-72be-b085-a9811ab4fb6b",
  "text": "Клиент [ФИО_1], паспорт [ПАСПОРТ_1]",
  "entities": [
    { "type": "FIO", "start": 13, "end": 51, "replacement": "[ФИО_1]", "score": 0.95, "source": "dictionary" },
    { "type": "PASSPORT", "start": 68, "end": 79, "replacement": "[ПАСПОРТ_1]", "score": 0.95, "source": "regex" }
  ],
  "degraded": false,
  "stats": { "tokens": 21, "latency_ms": 1.41 }
}
```

```bash
curl -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -H 'X-System-Id: crm-assistant' -H 'X-System-Key: crm-secret' \
  -d '{"operation":"demask","session_id":"01a0d250-…","text":"Уважаемый [ФИО_1], заявка принята."}'
# {"text":"Уважаемый Иванов Иван Иванович, заявка принята.","restored":1,"unresolved":0,…}
```

`"dry_run": true` возвращает перечень того, что было бы замаскировано, не меняя текст.
Ошибки приходят в едином формате `{"error":{"code","message","request_id"}}` с понятным
сообщением на русском; превышение лимита — `429` с `Retry-After`.

## Настройка

Добавьте систему в `systems`, указав её `id`, SHA-256 её ключа и профиль правил (`strict`,
`cards_only` или свой из `profiles`). Набор маскируемых типов ПД и способ маскирования
(`placeholder`, `partial`, `token`, `synthetic`, `hash`, `redact`) задаётся в профиле,
а точечные отличия — в `overrides` системы. Демаскирование включается флагом `demask: true`
у системы и маршрута. Какие ручки LLM проверяются, а какие пропускаются (`bypass`) или
запрещены (`block`), описывается в `routes`, включая JSON-пути полей для маскирования.
Изменения применяются без перезапуска: сервис перечитывает файл сам, а при ошибке
продолжает работать на предыдущей версии.

<details>
<summary><b>Пример: платёжный бот, которому нужны только карты</b></summary>

<br/>

```yaml
systems:
  payments-bot:
    enabled: true
    key_sha256: "env:PDG_KEY_PAY_SHA256"
    profile: cards_only
    demask: true
    rate_limit_rps: 500
    overrides:
      types:
        PHONE: { mask: partial }
        PIN:   { disabled: true }
```

Профиль `strict` маскирует ПИН и CVV только рядом с номером карты:

```yaml
combination:
  rules:
    PIN: { requires_any: [CARD_NUMBER], scope: document }
    CVV: { requires_any: [CARD_NUMBER], scope: window, window_chars: 200 }
  always_mask: [CARD_NUMBER, PASSPORT, INN]
```

</details>

### Какие данные распознаются

| Группа | Типы |
|---|---|
| Личность | ФИО, дата и место рождения, гражданство |
| Паспорт РФ | серия и номер, орган выдачи, код подразделения, дата выдачи |
| Другие документы | водительское удостоверение, загранпаспорт, СНИЛС, полис ОМС, свидетельство о рождении, военный билет |
| Адрес | целиком и по частям: страна, индекс, регион, город, улица, дом, квартира |
| Контакты | email, телефон |
| Финансы | ИНН физлица и организации, номер карты, CVV, ПИН, имя держателя |

Новый тип добавляется записью в `pd_types` и регулярным детектором в конфиге — без
изменения кода. Даты распознаются в любом порядке полей и прописью, номера документов —
с разделяющими словами («серия 4509 номер 123456»).

## Надёжность и приватность

- **Ничего исходного в логах.** Логи — структурированный JSON с типами и смещениями сущностей,
  без значений. Секреты обёрнуты в `Sensitive<T>`: `Debug` печатает заглушку, память
  зануляется через `zeroize`.
- **Деградация вместо падения.** NER вызывается только на окнах с сигнальными словами,
  за circuit breaker; при отказе ответ собирается на правилах и помечается `degraded: true`.
- **SLA зашит в сервер.** Таймаут запроса 950 мс, `max_inflight` 4096, лимит тела 2 МБ,
  per-system rate limit с `429` и `Retry-After`, graceful shutdown по SIGTERM.
- **Метрики без ПД.** Latency по стадиям, RPS, токены в секунду, число сущностей по типам,
  деградации, утечки после маскирования, операции vault — в Prometheus на служебном порту.

## Структура

```text
src/
  controller/   HTTP на hyper без фреймворков: /process, прокси, admin, middleware
  service/      бизнес-логика
    detect/       детекторы по типам ПД и валидаторы контрольных сумм
    pipeline.rs   нормализация → детекция → разрешение → маскирование → самопроверка
    relevance.rs  фильтры: публичные лица, отделения банка, контекст организации
    mask.rs       способы маскирования
    demask.rs     обратная подстановка по сессии
  adapter/      vault (memory, Redis), NER (HTTP, ONNX), клиент LLM, circuit breaker
  domain/       сущности, типы ПД, трейты — без зависимостей наружу
  config/       модель YAML, загрузка, компиляция политик, горячая перезагрузка
  infra/        криптография, логирование, метрики, rate limit
config/
  config.yaml   системы, профили, маршруты прокси

tests/          интеграционные тесты, прокси, контракт Приложения A, золотой набор
```

## Ограничения

> Сказано прямо, чтобы не пришлось искать.

- **Золотой набор маленький.** 32 текста — это регрессионная страховка, а не оценка
  на реальном трафике. 1.000 на нём не означает 1.000 в проде.
- **NER выключен по умолчанию.** Адаптеры HTTP и ONNX есть, но модель в репозиторий
  не входит; ФИО и адреса распознаются словарями и правилами.
- **Замеры сняты на одной машине.** Генератор и сервис делили процессор, сети между ними
  не было. На стенде с сетью абсолютные цифры будут выше.
- **Vault в памяти по умолчанию.** Сессии живут 15 минут и не переживают рестарт;
  для нескольких реплик нужна сборка с `--features redis` и `vault.mode: redis`.
